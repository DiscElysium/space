第1页｜轨道工坊
当前游戏概述与核心问题。

[strap]
建造一座工厂，驾驶你构筑的系统。

[question]
理解一套系统，能否改变玩家移动、攻击与操控的方式？

[intro]
SPACE 是一款自动化建造沙盒。玩家探索并收集资源、建造飞船，再驾驶亲手组装的系统。供给路径与触发分配决定已安装设备如何响应，因此，对系统理解的加深可以改变飞船的操控手感与行动方式。

[insets]
原始实机 / 九块空甲板开局

[h1]
让成长伴随探索

[b1]
每次扩建都保留在玩家用于探索的载体上。获得的资源逐渐转化为能够运行的结构、供给路径与新能力。

[h2]
让理解影响操控

[b2]
推进器布局、供给与触发分组共同改变输入的响应。成长因此不仅改变产量，也改变载体如何行动。

[h3]
在使用中形成系统

[b3]
暂停编辑、试用构筑，再围绕试航中发现的需求扩展系统。当前框架已经可玩，学习曲线仍需玩家观察。

第2页｜三种成长，如何汇入同一艘飞船
用三种成长作为个人分析框架，说明参考如何转化为自己的设计目标。

[title]
三种成长，如何汇入同一艘飞船

[intro]
我用三个视角理解游戏中的成长：玩家获得了什么、行动变得多么熟练，以及对系统理解得多深。我希望玩家能够通过亲手建造，让理解的成长改变操作。

[motivation_h]
为什么让成长集中在载体上？

[motivation]
把生产系统放到飞船上，可以让建造的成果持续参与使用。资源转化为始终跟随玩家的载体；试航中遇到的问题，也为下一次扩建提供具体目的。

[raft_h]
Raft / 让获得的成长成为可见载体

[raft]
Raft 让不断积累的建造成果随着玩家一起移动。我希望每座新结构与每条供给路径都能在探索中继续发挥作用，让成长表现为一艘持续变化的载体。

[noita_h]
Noita / 让知识转化为能力

[noita]
在我的体验中，Noita 将获得、理解与操作紧密地联系在一起。不过，不同构筑可能要求截然不同的操作，使操作熟练度的积累不总是连续的。因此，我希望建立更稳定、又能够被玩家不断重新组织的控制基础。

[network_caption]
早期团队项目 / 原始组件美术

[synthesis_h]
被带入 SPACE 的问题

[synthesis]
第一个游戏通过触发网络探索这一问题。SPACE 则将同一愿望重新组织为自动化系统，并把它放在玩家亲自驾驶的载体上。

[automation_images]
shapez：运输结构；Mindustry：供给参与战斗

[automation_h]
自动化 / 将理解继续延伸到行动

[automation]
游玩 shapez 时，我的注意力主要集中在规划与吞吐效率上。我希望生产知识还能进一步改变直接操控的反馈。Mindustry 中供给参与战斗的关系，也帮助我思考生产与行动的联系。

[goal1_h]
01 / 获得成长

[goal1]
资源、设备与甲板空间积累为持续存在的飞船。每次增加都应当支持探索，或带来新的行动可能。

[goal2_h]
02 / 操作成长

[goal2]
练习让时机把握与协同操作更加熟练。稳定的控制基础，应当让已有经验能够在扩建后继续发挥作用。

[goal3_h]
03 / 理解成长

[goal3]
理解供给、布局与触发之间的关系，让玩家能够重新组织飞船的响应方式，而不仅是增加产量。

第3页｜建造如何成为操控的一部分
以探索收集、建造配置、驾驶操作解释核心玩法，突出供给和触发如何改变手感。

[title]
建造如何成为操控的一部分

[intro]
探索收集、建造飞船，再驾驶操作。我用供给与触发将这些活动连接起来，让玩家既能决定何时行动，也能亲手构筑行动得以发生的条件。

[loop]
核心循环：探索收集 → 建造与配置飞船 → 驾驶操作 → 带着新需求返回建造。

[input_h]
输入 / 触发器 / 设备

[input]
按键激活触发器，触发器再控制已分配设备的启停。供给决定这些设备是否具备运行条件，以及能够持续输出多少能力。

[callout_store]
储存柜

[callout_route]
传送带

[callout_input]
D 按键输入

[edit_h]
01 / 放置与编辑

[edit]
暂停后可在二维或三维视角中建造，放置与旋转设备，并借助回收与撤销反复试验。自动化供给会逐步取代手工投料。

[supply_h]
02 / 连接供给与触发

[supply]
将燃料或弹药送到对应设备。路径提供运行与持续输出所需的资源，触发器决定何时启用。供给中断后，设备储存的燃料仍可让它短暂继续运行。

[ammo_h]
生产改变能够持续进行的行动

[ammo]
生产改变飞船能够持续进行的行动。理解一条路径，因此可以改变加速、武器可用性或协同方式，而不仅是提高产量。

[flight_caption]
真实三维截图 / 较早的预置布局

[fly_h]
03 / 试航与扩建

[choice1_h]
物理 / 推进器位置参与操控

[choice1]
我围绕飞船定制推力、扭矩、惯量与碰撞规则。推进器的位置和朝向参与决定加速、旋转，以及不同朝向的行驶方式。

[choice2_h]
稳定性 / 扩展已经运行的系统

[choice2]
甲板决定质量。以核心甲板为稳定旋转参考，让飞船扩建后原有推进器关系仍然可预期。我希望小修改能够引向扩建，而不是迫使玩家重做整个操控系统。

[choice3_h]
学习 / 让同一按键产生不同的响应

[choice3]
布局、供给与触发分组共同改变按键响应。我希望理解能够改变手感与机动可能，而这种长期学习曲线仍需要玩家测试。

[assist]
较弱的无燃料 WASD / Q / E 微推，为首次试航与脱困提供更平滑的过渡。已安装推进器仍然依赖玩家亲手搭建的系统。

第4页｜第一个作品：一次范围过大的实验
展示第一款团队作品已经完成的流程与工作量，并分析它为什么没有实现预期的学习体验。

[title]
第一个作品：一次范围过大的实验

[intro]
我的第一个游戏是六人合作的 Unity 项目，也是我第一次带队。我围绕一套分支触发系统展开设计，希望将法术编辑、资源收集与建造连接起来。

[system_h]
01 / 分支式组件系统

[credits]
Unity / 六人团队 / 我的第一次带队经历

[combat_h]
04 / 近战分支

[system]
点击六边形源格后，触发会沿连接的格子传递。同一逻辑可以用于背包编辑和地图建造；粒子动能则把运动与伤害联系起来。团队贯通了包含两场 Boss 遭遇的可玩流程，并完成了利用反作用推进的火箭发动机原型。

[particles]
02 / 粒子射击输出

[boss]
03 / 俯视 Boss 遭遇

[reflection_h]
回顾性的设计反思

[r1_h]
01 / 第一个有效结果出现前，学习成本过高

[r1]
第一次制作游戏就选择复杂编辑系统，使入门成本很高。组件可能直到后续组合中才显现价值，但玩家更早就必须判断是否保留它。我需要提供有用的阶段性结果，以及更及时的假设验证机会。

[r2_h]
02 / 流程贯通，不等于学习路径清晰

[r2]
这套循环将战斗奖励与建造连接起来，也提供了相对安全的实验场景。但流程贯通并不保证玩家理解了它。编辑与反馈之间的距离，使庞大的可能性空间难以被有目的地探索。

[r3_h]
03 / 制作范围超过了核心实验所能承载的程度

[r3]
两场 Boss、角色、环境与额外战斗系统不断扩大工作量。第一次带队时，我没有及时保护核心实验。项目没有实现我最初期待的学习体验，但为我积累了技术基础，以及组织团队与多种创作工作的经验。

[bridge_h]
走向 SPACE / 重新组织设计

[bridge]
我保留了“让理解转化为能力”的愿望。重做将密集的触发编辑器转化为同一艘飞船上的可见自动化，并先分开检验建造与物理，再将它们重新连接。

第5页｜通过删减与实验，形成更集中的系统
说明重做中的两项实验与几次取舍如何服务于同一体验，而不只是展示画面升级。

[title]
通过删减与实验，形成更集中的系统

[intro]
我先将建造与运输、运动与碰撞分开，通过各自的原型做出更清楚的取舍。后续维度、场景与界面的变化，都服务于同一目标：让注意力集中在构筑系统及学习如何操作它。

[s1_h]
01 / 二维玩法与技术验证

[s1]
二维原型用于检验建造、路径与设备控制。当地图建设削弱探索动力与自动化需求时，我删除了这一建设场景。

[s2_h]
02 / 三维表现与交互

[s2]
我在三维中试验光影与渲染。空间反馈与环境交互更加丰富，但精确建造也变得不够直观。

[s3_h]
03 / 太空幻想与 NASA 朋克

[s3]
太空场景重新集中于航天与移动工坊，以 NASA 朋克的工业语言组织整体风格。

[s4_h]
04 / 共用视图与更简洁的界面

[s4]
建造提供二维与三维两种视图；编辑、研发与航行复用背包、配置及选中界面。

[scope_h]
范围取舍 / 将成长集中于同一载体

[scope]
当地面建造与探索争夺重心，并削弱自动化需求时，我选择只允许在船上建造，让新资源成为继续旅行与扩展同一载体的理由。

[principle]
共用状态让二维与三维视图保持连续。更简洁的界面与首次试航引导，让玩家将注意力放在能够运行的供给和控制系统上。

[a_h]
A / 构建实验

[a_caption]
编辑细节：朝向与接口 / 立体试运行

[a]
我单独检验占格、背包、运输与生产，通过清楚的朝向和接口线索，以及放置、旋转与撤销，先检查建造流程，再将其与直接操控重新连接。

[b_h]
B / 运动与碰撞实验

[b]
我单独检验推力与接触：甲板决定质量，核心提供稳定旋转参考，推进器位置改变力与扭矩，相反碰撞偏移产生相反旋转响应。

[outcome_h]
已有结果与下一步

[outcome]
当前可玩框架已连接建造、供给、触发、共用视图编辑与首次试航引导。下一步是观察玩家如何判断故障，并据此改变控制策略。
